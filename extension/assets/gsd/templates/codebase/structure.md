```markdown
# Codebase Structure

**Analysis Date:** 2025-01-20

```
my-project/
├── src/               # Application source code
│   ├── commands/      # CLI command handlers
│   ├── services/      # Business logic services
│   └── utils/         # Shared utilities
├── .gsd/              # GSD skill resources
│   ├── references/    # Principle documents
│   ├── templates/     # File templates
│   └── workflows/     # Multi-step procedures
├── .github/           # GitHub configuration
│   ├── agents/        # GSD agent definitions
│   └── copilot-instructions.md  # Agent instructions
├── tests/             # Test files
├── package.json       # Project manifest
└── README.md          # User documentation
```

## Directory Purposes

**src/commands/**
- Purpose: CLI command definitions and handlers
- Contains: *.ts files (one per command)
- Key files: new-project.ts, plan-phase.ts, execute-plan.ts
- Subdirectories: None (flat structure)

**.gsd/references/**
- Purpose: Core philosophy and guidance documents
- Contains: principles.md, questioning.md, plan-format.md
- Key files: principles.md - system philosophy
- Subdirectories: None

**.gsd/templates/**
- Purpose: Document templates for .planning/ files
- Contains: Template definitions with frontmatter
- Key files: project.md, roadmap.md, plan.md, summary.md
- Subdirectories: codebase/ (for stack/architecture/structure templates)

## Key File Locations

**Entry Points:**
- `src/index.ts` - CLI entry point

**Configuration:**
- `package.json` - Project metadata, dependencies, bin entry
- `.gitignore` - Excluded files

**Core Logic:**
- `src/services/` - Business logic services

**Testing:**
- `tests/` - Test files

**Documentation:**
- `README.md` - User-facing installation and usage guide
- `.github/copilot-instructions.md` - Agent instructions for working in this repo

## Naming Conventions

**Files:**
- kebab-case.md: Markdown documents
- kebab-case.ts: TypeScript source files
- UPPERCASE.md: Important project files (README, CHANGELOG)

**Directories:**
- kebab-case: All directories
- Plural for collections: templates/, commands/, workflows/

**Special Patterns:**
- index.ts for directory barrel exports
- *.test.ts alongside source files
```

<guidelines>
**What belongs in STRUCTURE.md:**
- Physical directory layout
- Purpose of each directory
- Key file locations (entry points, config, core logic)
- Naming conventions
- Where to add new code
- Special/generated directories

**What does NOT belong here:**
- Architecture patterns (that's ARCHITECTURE.md)
- Technology choices (that's STACK.md)
- File-by-file documentation (too detailed)
- How code works (defer to reading code)

**When filling this template:**
- Run file listing (tree or equivalent)
- Identify major directories
- Note naming patterns
- Find entry points
- Locate test directories
- Note generated/special directories

**Useful for phase planning when:**
- Adding new features (where to put files?)
- Understanding codebase organization
- Creating new modules (follow existing patterns)
- Finding specific types of code
</guidelines>
